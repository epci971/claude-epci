# Task 006: Implement PRD-to-Notion injector

## Objective

Implement the module that injects PRD.json tasks into the Notion OpenClawTasks database. This enables the full pipeline: `/brainstorm` → `/spec` → `prd_injector` → `python loop.py` → `implement-auto`. The injector creates Notion pages with correct properties, acceptance criteria in the body, and bidirectional dependency relations (US4, decision D10).

---

## Context

Decision D10 establishes that OpenClaw libs are reusable by `/spec` for PRD-to-Notion injection. The `prd_injector.py` module reads a PRD.json file (generated by /spec, schema: prd-v2.json) and creates corresponding pages in the Notion OpenClawTasks database.

The OpenClawTasks schema (`src/schemas/notion-bdd-openClawTasks.json`) defines:
- Property mapping: Name, Story ID, Description, Category, Type, Complexite, Priorite, Statut, Spec Path
- Page body template: acceptance criteria as checklist, subtasks as todo list
- Dependency relations: "Bloque par" (two-way, self-referencing)

Two-pass algorithm required:
1. Pass 1: Create all pages (properties + body)
2. Pass 2: Patch dependency relations (need all page IDs first)

## Acceptance Criteria

### AC1: Create pages from PRD.json

- **Given**: A PRD.json with 5 tasks generated by /spec
- **When**: `inject_prd(prd_path, database_id, project_id)` is called
- **Then**: 5 pages are created in Notion with correct Name, Story ID, Description, Priorite, Complexite, Statut="A faire"

### AC2: Acceptance criteria in page body

- **Given**: A task with 3 acceptance criteria (Given-When-Then format)
- **When**: The page is created
- **Then**: Page body contains a "Criteres d'acceptation" section with 3 items as to_do blocks (unchecked)

### AC3: Dependency relations resolved

- **Given**: task-002 depends on task-001 in PRD.json
- **When**: Dependency resolution runs (second pass)
- **Then**: "Bloque par" relation on task-002's page correctly points to task-001's page ID

### AC4: Duplicate detection

- **Given**: A Story ID already exists in the Notion database for this project
- **When**: `inject_prd` tries to create a page with the same Story ID
- **Then**: Existing page is skipped with WARNING log, no error raised

## Steps

### Step 1: Implement PRD.json parser and property mapping (25 min)

**Input**: PRD v2.0 schema (`src/schemas/prd-v2.json`), OpenClawTasks schema

**Actions**:
1. Create `prd_injector.py`
2. Implement `load_prd(prd_path)`:
   - Read and parse PRD.json
   - Validate required fields (title, slug, tasks)
   - Return structured PRD object
3. Implement `task_to_notion_properties(task, project_id)`:
   - Map PRD task fields to OpenClawTasks properties:
     - `title` → Name (title type)
     - `id` → Story ID (text)
     - `title` → Description (text) — or task objective if available
     - `complexity` → Complexite (S→Simple, M→Moyenne, L→Complexe)
     - Priority based on task order: first 30% → P0, next 30% → P1, rest → P2
     - Statut → "A faire"
     - Spec Path → path to task-XXX.md file
   - Set Projet relation if project_id provided

**Output**: PRD parser and property mapper

**Validation**: Correct Notion property format from sample PRD task

### Step 2: Implement page creation with acceptance criteria body (25 min)

**Input**: create_page from task-002, OpenClawTasks page content template

**Actions**:
1. Implement `build_page_body(task)`:
   - Create "Criteres d'acceptation" heading
   - For each AC: create to_do block with `{AC.id}: {AC.title} — Given {given}, When {when}, Then {then}`
   - Create "Sous-taches" heading (if task has steps)
   - For each step: create to_do block with `{step.id}: {step.title} ({step.duration_minutes} min)`
2. Implement `create_task_page(notion_client, database_id, task, project_id)`:
   - Build properties via `task_to_notion_properties`
   - Build body via `build_page_body`
   - Call `notion_client.create_page(database_id, properties, body)`
   - Return created page ID

**Output**: Page creation with structured body

**Validation**: Created page has correct properties and body blocks

### Step 3: Implement dependency resolution (two-pass algorithm) (25 min)

**Input**: PRD dependencies_graph, created page IDs

**Actions**:
1. Implement `inject_prd(prd_path, database_id, project_id, notion_client)`:
   - Load PRD
   - Pass 1: Check for duplicates, create all task pages, collect `{task_id: page_id}` mapping
   - Pass 2: For each dependency edge in `dependencies_graph.edges`:
     - Get source and target page IDs from mapping
     - Update target page's "Bloque par" relation to include source page ID
   - Handle rate limiting (sleep between API calls)
   - Log summary: created, skipped, relations patched
2. Implement `check_duplicates(notion_client, database_id, story_ids)`:
   - Query Notion for existing pages with matching Story IDs
   - Return set of already-existing Story IDs

**Output**: Complete injection module with dependency resolution

**Validation**: Dependencies correctly linked between pages

### Step 4: Write unit tests including duplicate detection (15 min)

**Input**: Functions from steps 1-3

**Actions**:
1. Test PRD loading and validation
2. Test property mapping (complexity, priority)
3. Test page body construction (AC + steps)
4. Test duplicate detection (skip with warning)
5. Test dependency resolution (edge patching)

**Output**: Complete test file

**Validation**: All tests pass
