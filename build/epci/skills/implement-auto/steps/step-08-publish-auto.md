# Step 08: Publish (Auto)

## MANDATORY EXECUTION RULES:

- NEVER call AskUserQuestion
- ALWAYS clean up worktree (except with --skip-publish)
- ALWAYS update JSON output with publish results BEFORE worktree removal
- ALWAYS print publish summary to stdout
- NEVER push or create PR for FAILED status

## EXECUTION PROTOCOLS:

### 1. Check Skip Condition

```
IF flag_skip_publish:
  Log: "[implement-auto] Publish skipped (--skip-publish)"
  Update JSON: publish.skipped = true
  Print summary and END (no push, no PR, no cleanup)
```

If `--skip-publish` is set, skip everything. The orchestrator manages post-processing.

### 2. Read Current Status

Read from the execution context (determined by step-06):

```
status = json.status          # SUCCESS | PARTIAL | FAILED
feature_slug = json.feature.slug
branch = json.feature.branch  # feature/{feature-slug}
```

### 3. Push Branch to Origin

**IF status is SUCCESS or PARTIAL:**

```bash
git push -u origin feature/{feature-slug}
```

Error handling:

| Error | Detection | Action |
|-------|-----------|--------|
| No remote configured | `git remote` returns empty | Warning, skip PR, go to cleanup |
| Push rejected | Exit code != 0 | Retry once, then error, skip PR, go to cleanup |
| Branch already pushed | Push succeeds or "up to date" | OK, continue |

Record: `publish.pushed` = true/false, `publish.push_error` = error message or null.

**IF status is FAILED:**

Skip push. `publish.pushed` = false.
Log: `[implement-auto] Push skipped (status FAILED)`

### 4. Create Pull Request

**Preconditions:** `publish.pushed` is true.

#### 4a. Check gh CLI

```bash
command -v gh >/dev/null 2>&1
```

If unavailable: warning "gh CLI not installed, PR creation skipped", `publish.pr_url` = null, `publish.pr_error` = "gh_not_installed", go to cleanup.

#### 4b. Check gh Authentication

```bash
gh auth status >/dev/null 2>&1
```

If not authenticated: warning "gh not authenticated, PR creation skipped", `publish.pr_url` = null, `publish.pr_error` = "gh_not_authenticated", go to cleanup.

#### 4c. Detect Default Branch

```bash
DEFAULT_BRANCH=$(gh repo view --json defaultBranchRef -q .defaultBranchRef.name 2>/dev/null || echo "main")
```

#### 4d. Build PR Body

Construct the PR body from JSON output data using this template:

```markdown
## [implement-auto] {feature_slug}

**Status**: {status} {SUCCESS: checkmark | PARTIAL: warning}
**Branch**: `feature/{feature_slug}`
**Generated by**: implement-auto (headless EPCI)

### Metrics

| Metric | Value |
|--------|-------|
| Components | {success_count}/{total_components} successful |
| Tests | {tests_passing} passing, {tests_failing} failing |
| Files created | {files_created} |
| Files modified | {files_modified} |

### Self-Review

- Status: {checks.self_review.status}
- Checks: {items_passed}/{items_checked} passed
- Findings: {items_warned} warnings

{IF status == PARTIAL}
### Partial Implementation

The following components require manual attention:

| Component | File | Error |
|-----------|------|-------|
| {name} | `{file}` | {error} |
{END IF}

### Feature Document

See `{feature_doc_path}` for full implementation details.

{IF warnings exist}
### Warnings

- **{phase}**: {message}
{END IF}

---
*Generated by implement-auto (headless EPCI)*
```

#### 4e. Create PR

For **SUCCESS**:

```bash
gh pr create \
  --title "feat({scope}): {feature-slug}" \
  --body "$PR_BODY" \
  --base "$DEFAULT_BRANCH" \
  --head "feature/{feature-slug}"
```

For **PARTIAL**:

```bash
gh pr create \
  --title "feat({scope}): {feature-slug} [PARTIAL]" \
  --body "$PR_BODY" \
  --base "$DEFAULT_BRANCH" \
  --head "feature/{feature-slug}" \
  --draft
```

Where `{scope}` is derived from the feature slug or spec context.

Error handling:
- **PR already exists**: Use `gh pr view feature/{feature-slug} --json url -q .url` to retrieve existing URL, add warning.
- **Create fails**: Add error, `publish.pr_url` = null, proceed to cleanup.

Record: `publish.pr_url` = PR URL, `publish.pr_draft` = true/false.

### 5. Auto-Merge (Optional)

**Precondition:** `flag_auto_merge` is true AND `publish.pr_url` is not null.

```bash
gh pr merge "feature/{feature-slug}" --auto --squash
```

Record: `publish.auto_merge_enabled` = true/false.

If the command fails (auto-merge not enabled in repo settings): add warning, `publish.auto_merge_enabled` = false. The PR stays open for manual merge.

If `flag_auto_merge` is false: `publish.auto_merge_enabled` = false.

### 6. Update JSON and Persist Results

**CRITICAL: This must happen BEFORE worktree removal (step 7).**

Update `.implement-auto-output.json` with the publish section:

```json
{
  "publish": {
    "pushed": true,
    "push_error": null,
    "pr_url": "https://github.com/org/repo/pull/123",
    "pr_draft": false,
    "pr_error": null,
    "auto_merge_enabled": false,
    "worktree_cleaned": false,
    "skipped": false
  }
}
```

Also update:
- `phases.completed` += "publish"
- `phases.current` = null

Copy the JSON to a persistent location in the main repo:

```bash
MAIN_REPO=$(git worktree list | head -1 | awk '{print $1}')
mkdir -p "$MAIN_REPO/.implement-auto-results"
cp .implement-auto-output.json "$MAIN_REPO/.implement-auto-results/{feature-slug}.json"
```

### 7. Clean Up Worktree

This step ALWAYS executes (for SUCCESS, PARTIAL, and FAILED).

```bash
# Resolve main repo path
MAIN_REPO=$(git worktree list | head -1 | awk '{print $1}')
WORKTREE_PATH=$(pwd)

# Change to main repo (cannot remove worktree from inside it)
cd "$MAIN_REPO"

# Remove worktree
git worktree remove "$WORKTREE_PATH" --force
git worktree prune
```

Error handling:
- Remove fails: add warning, `publish.worktree_cleaned` = false, continue.
- On failure, do NOT attempt more aggressive cleanup (leave for manual intervention).

Update JSON copy: set `publish.worktree_cleaned` = true (update the copy in `.implement-auto-results/`).

The branch is NOT deleted — it is preserved for the PR.

### 8. Print Publish Summary

Output to stdout:

```
[implement-auto] Publish complete
  Pushed: {yes/no}
  PR: {pr_url or "skipped" or "failed"}
  PR Draft: {yes/no}
  Auto-merge: {enabled/disabled}
  Worktree: {cleaned/preserved}
  Results: {main_repo}/.implement-auto-results/{feature-slug}.json
```

## CONTEXT BOUNDARIES:

- This step expects: Final status, feature metadata, committed changes, JSON output file
- This step produces: Pushed branch, PR (optional), cleaned worktree, persisted JSON with publish section

## NEXT STEP TRIGGER:

This is the final step. Execution ends here.
